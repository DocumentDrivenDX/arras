# US-079: Create an entity from a type's list

**Feature**: FEAT-011 — Graph Browser
**Feature Requirements**: BRW-27
**PRD Requirements**: FR-67
**Priority**: P2
**Status**: Draft

## Story

**As a** module builder or administrator
**I want** to press New on a type's list, fill in the declared action's form and land on the entity I created
**So that** that I add an entity without leaving Explore or knowing which action creates it

## Context

New is built from a declared action whose effects are exactly one `create` of the type and links that tie the created entity to others (SD-013 Rule 2). Where several such actions fit a type, a choice offers them, the one with the fewest inputs first. Nothing is offered that the module has not declared, and nothing to a viewer the host has not made an operator.

## Walkthrough

1. alice opens the `Solution` list and turns edit mode on; `New solution` is shown.
2. He presses it; a form asks for every input of the declared action; the key is an ordinary field unless the action generates it.
3. He fills it in, choosing the use case in the picker, and presses Validate; the effects are listed as text. He presses Create; the action is invoked as him.
4. The page of the created `Solution` opens, with focus on its title.
5. carol opens the same list; no lock and no New control are present.

## Acceptance Criteria

- [ ] **US-079-AC1** — Given a type for which a declared action's effects are exactly one `create` of that type and any number of `link` effects of which one end is the created alias, when an operator opens the type's list and turns edit mode on, then **New <type>** is offered (the lock alone before that); for a type with no such action, or an action with any other effect shape, it is not
- [ ] **US-079-AC2** — Given the form, when it opens, then it asks for every input of the action: a reference input is the picker (a filter above a dropdown of the referenced type's entities; the key field where the type cannot be listed), a list input is one value per line, a record input is JSON with the server's violations shown by path, and the key is an ordinary field, unless the action generates it (CONTRACT-003); a key already used is refused when the action is validated, and the refusal shows in the dialog
- [ ] **US-079-AC3** — Given several create actions that fit a type, when New is pressed, then a `Select` offers them with the one with the fewest inputs first
- [ ] **US-079-AC4** — Given a valid form, when it is validated and then created, then the action is validated and invoked as the viewer (Create is offered once the validation has passed), and the created entity's page opens from the key of the validated `create` effect, confirmed by the receipt's ref of the created type, whether the key was asked for or generated by the action (CONTRACT-003)
- [ ] **US-079-AC5** — Given an entity just created, when its page opens, then it is read at the default consistency (`latest`, served only by the module's record store), so it is not shown as "not available"; where the receipt does not name the created entity, the receipt is shown instead and nothing is opened
- [ ] **US-079-AC6** — Given a refusal or a violation, when the action is submitted, then it is shown in the dialog (a violation that names an input at that field), the values are kept, nothing is created, and a 401 offers Sign in again where the host gave `onUnauthorized`
- [ ] **US-079-AC7** — Given a viewer who is not an operator (`as carol: absent`), when the list is opened, then New is absent and no text refers to it
- [ ] **US-079-AC8** — Given a session that creates an entity, when the requests, the log lines, the errors and the address are inspected, then no key and no person is in a path, a query string, a log line or an error, and an entity key appears only in the fragment or in a POST body

## Edge Cases

- **A create action with a link to a missing entity**: the validation refusal is shown at the form; nothing is created.
- **A key that exists**: the validation refuses it (`conflict (exists)`) and the dialog shows the refusal; Create stays disabled.
- **A host that offers no edits**: New is not shown.

| Scenario | AC ID | Input / State | Action | Expected Result |
|----------|-------|---------------|--------|-----------------|
| Offered for a create action | US-079-AC1 | an `Add` action creating `Solution` | open the list as alice | `New Solution` shown |
| Form from inputs | US-079-AC2 | the action's inputs | open the form | Every input asked; list, record and ref inputs as specified |
| Several create actions | US-079-AC3 | two actions that create the type | press New | A choice, fewest inputs first |
| Created entity opened | US-079-AC4 | a valid form with an asked key | submit | The new page opens from the validated `create` effect's key; the receipt's ref of the created type confirms it |

| Refusal kept inline | US-079-AC6 | an existing key | validate | Refusal shown in the dialog; values kept; Create disabled |
| Reader sees nothing | US-079-AC7 | carol | open the list | No lock, no New control, no text for it |
| No key in a URL | US-079-AC8 | a create | inspect requests, logs and errors | Key only in the fragment or a POST body |
