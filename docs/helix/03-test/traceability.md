# Acceptance Criteria Traceability Matrix

## Purpose

This matrix maps every acceptance criterion in the user stories (`US-<n>-AC<m>`, 439 in all) to the automated tests in this repository that prove it, or says why no test proves it yet. The tests run against the in-memory fakes in `src/arras/fakes.py`, which are the memory adapter (`memory` and `memory_replica`) and stand in for the production adapters, Truss (a reader and provider on Lakebase) and Ashlar (a reader on Unity Catalog), so this is the evidence the test plan (TP-001) asks for before the real adapters exist. Use it to find the work still owed in this repository (`gap` and `partial`) apart from the work that waits on another system (`blocked`).

## How to read it

Each criterion has one status:

| Status | Meaning |
|--------|---------|
| `covered` | A test in this repository exercises the criterion against the fakes and asserts what it says. |
| `partial` | A test proves part of it; the evidence column says what is still owed in this repository. |
| `blocked` | What is not proven needs a system this repository does not have: Truss, Ashlar, a real Postgres, Lakebase or Unity Catalog, the embedding host, UMF's reference validator, Weft, or latency measured at the host. Any part the fakes already prove is listed. |
| `gap` | Nothing proves it and nothing blocks it: a test, and sometimes code, is owed. |

Evidence names a test as `test_<file>::<function>`, a function in `tests/test_<file>.py`. `corpus <id>` is a case in `src/arras/conformance/corpus.json`; `tests/test_conformance.py` runs every case tagged for the provider role on the memory provider and every case tagged for the reader role on the memory replica. A test with fewer records than the criterion (for example two pages instead of three) counts when it proves the same behavior.

## Wording the contracts contradict

These criteria say something the current contracts do not. Each needs its wording settled, in the story or the contract, before its status can be `covered`.

| Criterion | What the criterion says | What the contract says |
|-----------|-------------------------|------------------------|
| US-019-AC1, US-023-AC3 | An action, import or registration on a read-only module is `Unsupported`. | A module whose provider is read-only cannot declare actions (CONTRACT-002), so invoking one is `Invalid` (`unknown_action`); `register` on it is `Invalid` (`read_only_module`). Only `import_records` is `Unsupported`, as CONTRACT-003's error table says; its `invoke` steps and its Refusals paragraph still name `Unsupported` for a read-only module. |
| US-019-AC2 | Only `invoke`, `invoke_batch` and `import_records` write. | `registry().register` and `attach` also write: they record an ontology revision (CONTRACT-002). |
| US-013-AC2 | An effect outside the closed list is refused unless a handler supplies it. | A handler returns effects in the same closed list (CONTRACT-003); it cannot add a new kind. |
| US-046-AC2 | One item can fail a precondition and the failure names the item. | Preconditions are declared over the action's inputs, not per `foreach` item (CONTRACT-003). |
| US-006-AC4 | A token from another deployment is refused. | A token the serving backend has not reached leads to waiting or `NotYetCurrent` (CONTRACT-001, CONTRACT-004); there is no refusal. |
| US-027-AC3 | With no grant, any operation is refused. | A read of a module the principal may not read answers as one that does not exist (`Invalid`, `unknown_type`), so its existence is not revealed (CONTRACT-001 Access, CONTRACT-004 `query`); actions and the registry still refuse. |
| US-024-AC3 | A corpus case at `latest` fails a replica that answers. | The corpus runs at the adapter's operations and has no consistency level; `latest` only from the record store is Arras's own test (CONTRACT-004). |
| US-050-AC3 | `destructiveHint` only when an effect is `delete` or `unlink`. | Also when the action has a handler (CONTRACT-007). |
| US-052-AC3 | `code` is `invalid`, `refused`, `unavailable`, `unsupported` or `not_yet_current`. | Also `precondition_failed` and `conflict` (CONTRACT-007). |
| US-052-AC11 | No protocol error except for a malformed request. | Calling a tool the registry no longer declares is a -32602 protocol error (CONTRACT-007, US-053-AC4). |
