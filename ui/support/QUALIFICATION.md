# Downstream theme qualification

`arras-ui-qualify <URL>` checks an HTTP(S) host using the public Arras UI in a real Chromium browser. Add `--host-build` when the page is a compiled host using `ArrasApp`, and `--console` when the route is the operator console. The command checks the public root, WCAG 2.1 A/AA axe rules, the 18 documented role tokens, color contrast, keyboard focus, and screenshots. For host builds it also verifies app-owned theme Button/Mark use and opens, searches, and dismisses the command palette while checking focus restoration.

Install `@playwright/test@1.63.0` and `@axe-core/playwright@4.13.0` in the invoking host and install a compatible Chromium browser before running the command. These are optional peer dependencies. The command never installs packages, downloads browsers, or accesses the network to obtain dependencies. Missing tools produce an actionable error.

Use `--output <dir>` to retain screenshots and a JSON receipt; by default they go to `arras-ui-qualification/` under the current directory. Use `--baselines <dir>` to compare against platform-specific PNG baselines. With no baseline directory, screenshots are captured and the receipt marks visual comparison unqualified. macOS compares baselines when supplied; other platforms report visual comparison skipped while still running every nonvisual gate. Updating is explicit and macOS-only: `--baselines <dir> --update-baselines`. Review updated images before accepting them. Unknown or malformed arguments exit with status 2; `--help` prints the supported arguments.

For installed-artifact validation, build and install the wheel-carried npm package into an external consumer and invoke its `arras-ui-qualify` bin. A completed receipt should be retained with the exact wheel, npm package, theme package, and runner hashes and the runtime versions used. The qualification fixture installs the Arras and theme tarballs from the selected cohort and obtains public tooling and React peers from the npm registry in an isolated temporary project.

The result qualifies only the tested host, theme, package cohort, browser, and platform. It is not a certification of other host applications or themes.

## Host-build fixture contract

`--host-build` does not check an arbitrary page. It checks a fixture page that the host builds from its own theme and the public Arras components, and the page must have the shape below. A page without it fails with the first requirement it misses: the runner prints that requirement and records it as `requirement` in the failure receipt, instead of only the phase name. Everything is checked in light and in dark (the runner sets the browser's `prefers-color-scheme`), with `--console` navigating to `#admin` of the given URL.

1. **A root.** The page renders at least one `.arras-root` (any Arras entry component renders one; a page may also wrap the fixture in `<div className="arras-root">`). The first `.arras-root` in the document is the one every check below reads, so the widgets sample, the tokens and the region must be inside it.
2. **Six marked widgets.** That first root contains at least one element matching each of `[data-theme-button]`, `[data-theme-text-field]`, `[data-theme-text-area]`, `[data-theme-select]`, `[data-theme-notice]` and `[data-theme-mark]`. The markers are attributes the host's own widgets put on their elements (`<button data-theme-button ...>`); Arras does not add them. The `@documentdrivendx/arras-ui/testkit/host` export `WidgetControls` renders the sample from whatever design system is in context, so a host only has to mark its widgets.
3. **A controls region with a keyboard opener.** An element with the role `region` and the accessible name `Downstream widget controls` (for example `<section aria-label="Downstream widget controls">`) inside the first root holds, in this tab order and with no other focusable element between them, a `button[data-theme-button]`, a `[data-theme-text-field]`, a `[data-theme-text-area]` and a `[data-theme-select]`. The runner focuses the first button, presses Tab to walk the others, and uses that button as the opener of the command palette.
4. **The public app, drawn through the host.** A `.arras-root` contains the app: for the Explore route an element matching `.gb` (`GraphBrowser` or `ArrasApp`), for `--console` an element matching `[data-testid="console-header"]`. The app is mounted beneath the host's `DesignSystemProvider`, and its brand is configured with `logo: "theme"` (for a compiled host, `<meta name="arras-brand" content='{"name":"...","logo":"theme"}'>` or the `brand` prop), so that it draws the host's Mark: the app must contain a `[data-theme-mark]`. With the opener focused, Ctrl/Cmd+K opens a dialog named `Command palette` whose combobox named `Search entities and commands` is a `[data-theme-text-field]` and which holds a `button[data-theme-button]`; Escape closes it and focus returns to the opener. The testkit `AcceptanceHost` satisfies the app part.
5. **Eighteen resolved role tokens.** The first root resolves all eighteen `--arras-*` role tokens in both schemes, with valid lengths and font families, and these contrasts: text, muted text on surface, sunken and ground at 4.5:1; on-accent on accent at 4.5:1; border on surface at 3:1; each of the four state colours on surface at 3:1.
6. **Axe.** No WCAG 2.0/2.1 A or AA violation on the whole page in either scheme.
7. **A measurable focus ring.** Each of the four region controls, when focused, shows an outline of at least 2px (or a box shadow) that reaches 3:1 against the colour behind it. That colour is computed by compositing the `background-color` of the control's ancestors up to `html`, then the browser canvas colour. The runner cannot measure, and so rejects, any ancestor with a `background-image` (a gradient on `body` or on the fixture's wrapper included) or an `opacity` other than 1. Give the ancestors of the controls a solid background colour and no gradient, image or opacity.

A prebuilt page (without `--host-build`) needs none of this: it needs an external theme stylesheet linked through `/theme-assets/`, a themed favicon, one `.arras-root`, a focusable control, the tokens and no axe violation.
